# KindGuard

*An SME Shield program.*

Website security scanner for SMEs, with results framed against baseline
EU digital-resilience expectations.

## Start here

**Just want to click through it right now, no setup?** Open `instant-demo.html`
directly in your browser (double-click it). It's a self-contained,
zero-install version of the whole product — scan flow, dashboard, premium
page, contact form — running entirely in your browser with simulated scan
results. See "About the instant demo" below for exactly what's real vs
simulated in it.

**Want the real thing, actually scanning real websites?** That's
`frontend/` + `backend/` — see "Running it for real" below.

## What's in this folder

## Design: Warm & Human

The visual direction is warm and approachable rather than the earlier dark
cyber-radar look: soft cream background, deep teal + warm gold accents,
Fraunces (serif) for headlines paired with Inter for body text. Colors and
type are defined as CSS custom properties in `frontend/src/styles/tokens.css`
and mirrored in `design/landing-mockup.html`.

The KindGuard brand mark (`frontend/src/components/BrandMark.jsx`) is real,
working SVG + CSS — the compass ring rotates continuously, the shield
pulses with a soft glow. It respects `prefers-reduced-motion`.

**Photos:** the Home and Contact pages now include real photography, sourced
from Lorem Picsum (a well-established placeholder-image service — free,
no attribution required, explicitly meant for exactly this use). These are
genuinely placeholders, not final brand photography — swap the `src` URLs
in `Home.jsx` and `Contact.jsx` for real photos of your team/business
before launch. A warm gradient overlay is applied over each photo (see
`.people-photo::after` / `.contact-photo::after` in the CSS) so whatever
photo loads still reads as on-brand.

**Interactive states:** every button, nav link, form field, and dashboard
row has explicit hover/focus/active styling (color shift, subtle lift,
focus rings on inputs) — not just the primary CTAs.

## About the instant demo

`instant-demo.html` is a single self-contained file — open it and it works
immediately, no `npm install`, no server, no internet required (photos
excepted). It's built to demonstrate the real interaction flow honestly:

- Scanning a URL runs a **deterministic simulation** — the same URL always
  produces the same score, because the result is generated by hashing the
  URL text rather than by actually checking anything. Try scanning
  `yourbusiness.com` twice; you'll get the same "result" both times.
- Two demo entries are pre-seeded on the dashboard so it doesn't look empty
  on first open.
- The contact form shows a success message but sends nothing anywhere.
- A banner at the top of the page says this plainly, so nobody mistakes a
  demo score for a real security assessment.

This is **not** a lesser version of the real app's code — it's a separate,
parallel implementation in plain HTML/CSS/JS sharing the same design system,
built specifically so you have something to click through without any setup
at all. The real scan logic lives only in `backend/`.

## Running it for real

```
cd backend
cp .env.example .env
npm install
npm run dev
```

The API starts on `http://localhost:4000`. SSL and header checks work out of
the box, no keys needed. Malware and domain-reputation checks need free API
keys (see `.env.example`) — without them they return a "skipped" warning
instead of failing, so the app still runs end to end.

```
cd frontend
cp .env.example .env
npm install
npm run dev
```

Opens on `http://localhost:5173`. Enter any real domain and it calls the
backend, then shows the actual report. Every scan is saved and shows up on
`/dashboard`.

I can't run `npm install` or reach the public internet from the environment
I build in, so while every file here is syntax-checked and the core logic
(scoring, rate limiting, SSRF guarding, history) is smoke-tested offline,
the live `npm install` + real-website-scanning path is worth a quick test
on your end before you rely on it.

## How the real scan works

1. **SSL/TLS** — connects directly to the site on port 443 and inspects the
   certificate's validity and expiry (`backend/services/sslCheck.js`).
2. **Security headers** — fetches response headers and checks for the four
   baseline protective headers (`backend/services/headersCheck.js`).
3. **Malware/hack detection** — checks the URL against Google Safe Browsing's
   threat lists (`backend/services/malwareCheck.js`).
4. **Domain reputation** — checks the domain against VirusTotal's vendor
   consensus (`backend/services/blacklistCheck.js`).
5. **EU-aligned checklist** — a plain-language summary derived from the four
   checks above (`backend/services/euChecklist.js`). Self-assessment aid,
   not a formal compliance certification.

`backend/services/scoreEngine.js` turns those into the 0–100 score and grade.
Every completed scan is saved via `backend/services/historyStore.js`.

## The "Premium" feature, concretely

Free tier is capped at 3 scans per rolling 30 days, per IP, enforced
server-side in `backend/services/rateLimiter.js` (configurable via
`FREE_MONTHLY_SCAN_LIMIT` in `.env`). Hit the limit and the frontend shows
an upgrade prompt linking to `/premium`. That's the real, working part.

What's **not** built: actual billing. The Premium page's CTA goes to the
contact form instead of a checkout, on purpose. When you're ready, that's a
Paystack/Flutterwave integration plus a real user-account system.

## Security hardening

- **SSRF protection** (`backend/services/ssrfGuard.js`) — KindGuard connects
  to whatever URL a stranger types in, so it resolves and blocks
  private/loopback/link-local targets (e.g. `127.0.0.1`, the
  `169.254.169.254` cloud metadata endpoint) before connecting, and pins
  the SSL/header checks to the validated IP to avoid a DNS-rebinding gap.
- **Dependencies** pinned to current versions with no known vulnerabilities
  as of this build: Express 5.2.1, cors 2.8.6, dotenv 17.4.2, helmet 8.2.0,
  express-rate-limit 8.5.2. Run `npm audit` yourself after install too.
- **Rate limiting** at two levels: the monthly free-tier quota (business
  logic) and a general 100-req/15-min API limiter (abuse prevention),
  plus a tighter 5/hour limit specifically on the contact form.
- **`trust proxy` defaults to off** — only enable it if KindGuard is
  actually behind a real reverse proxy, or the rate limiter becomes
  spoofable via `X-Forwarded-For`.
- Request bodies capped at 10kb; the generic error handler never leaks a
  stack trace to the client.

## Data storage caveat

Scan history and contact messages are stored in flat JSON files under
`backend/data/` (created automatically on first run) — dependency-free for
an MVP, but no multi-user separation (everyone sees the same dashboard,
since there's no login system) and not safe under real concurrent traffic.
Swap for Postgres/MongoDB when you add accounts.

## What's stubbed vs. what's real — please read before demoing

- **Real, working code:** SSL/header checks (IP-pinned against SSRF),
  scoring, monthly + general rate limiting, scan history persistence, the
  contact form (validated + rate-limited, saves to disk), all UI/animations.
- **Needs your API keys to activate:** malware + blacklist checks.
- **Placeholder, not real:** the email/WhatsApp on the Contact page, and all
  photography (Lorem Picsum placeholders — swap before launch).
- **Not built:** payment processing, user accounts/login, outbound email.
